# Dashboard — captured, not built

**Status: design captured 2026-08-15. The UI is deferred. The run-graph
schema is not** — recording starts now, because a dashboard built later can
only show data that was already being written.

## What it is for

One view answering: who is working on what, who is verifying it, who owns the
outcome, and how far along it is.

## The delegation tree

L0 decomposes into L1 nodes; an L1 node may decompose further. Every node has
an owner. **This is a work breakdown structure — it is not a spawn chain.**

Resources decompose and hand back a plan. **Only the router dispatches.** The
tree is recorded as data; the dispatch stays flat. That is what keeps the
fidelity decay and uncontrolled fan-out of recursive delegation out of the
system while still giving you the tree you want to look at.

See `charter.md` § Delegation.

## Three roles per node, and they are not the same thing

| Field | Meaning | Rule |
|---|---|---|
| `responsible` | the resource doing the work | one or more |
| `accountable` | owns the outcome | **exactly one.** Never two, never zero |
| `monitoring` | the resource verifying it | may be empty — and an empty verifier on a high-difficulty node is itself a finding |

Exactly one accountable per node is what keeps a deep tree legible. Two
accountables means nobody is.

## Progress is derived, never reported

An agent's "70% done" is self-assessment, and self-assessment is not evidence
anywhere else in this system. Progress comes from observable state
transitions only:

```
queued -> dispatched -> handed-back -> verified -> landed
                     \-> escalated
                     \-> blocked
                     \-> dropped        (dispatched, never returned)
```

A parent node's progress is a roll-up of its children's states. No percentages
are stored, ever — they can be rendered from state counts if a human wants one.

## Run-graph schema

Written to `ledger/runs/<run-id>.jsonl`, append-only. One line per state
transition, so the file is both the current state and the history.

```jsonc
{
  "run":        "2026-08-15-vendor-import",
  "node":       "L1.2",              // dotted path = position in the tree
  "parent":     "L0",
  "title":      "backfill vendor logos",
  "responsible":"implementer",
  "accountable":"architect",         // exactly one
  "monitoring": "adversarial-reviewer",
  "difficulty": "high",              // from docs/difficulty.md
  "effort":     "high",              // router's tier choice, for audit
  "state":      "dispatched",
  "at":         "2026-08-15T11:40:00Z",
  "budget":     { "unit": "turns", "limit": 20, "spent": 3 },
  "surfaces":   ["src/lib/data/vendors.ts"],   // file-conflict detection
  "blocked_on": null                  // shared-resource locks: e2e, commit lock
}
```

Two fields carry more weight than they look:

- **`surfaces`** makes file-conflict detection mechanical instead of a
  judgement the router has to remember.
- **`blocked_on`** is how shared exclusive resources (e2e, the commit lock, the
  dev server) become visible. Those collisions are invisible today, and they
  are the ones that have actually cost time.

## What the view must answer on open

Ranked by how often it will earn its place:

1. **What was dispatched and never came back** — MAST's *unaware of
   termination*. A run graph is the only thing that catches it.
2. **What is blocked, and on what** — especially anything waiting on e2e.
3. **What is waiting on me** — escalations that reached product altitude.
4. **What has no `accountable`, or two** — a schema violation, surfaced.
5. **Where did difficulty get mis-triaged** — `difficulty` vs the hand-back
   that followed. Feeds the router's own learning.

A view that shows activity without answering one of these is a status page,
and status pages do not get opened twice.

## Deferred

The rendering. Options when it matters: a static HTML artifact generated by
the weekly job, a terminal view over the JSONL, or a real UI. **Do not choose
yet** — the schema is what constrains the UI, not the reverse, and the schema
is now fixed.

The first version can legitimately be `jq` over `ledger/runs/`.
